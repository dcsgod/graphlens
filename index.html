GraphLens operates as a database-agnostic MCP Server. The schema—not the data—is the API. Each layer transforms raw graph structure into agentic capability.

Build the MVP

Three Steps to a Working Prototype

```
1
The Schema Crawler
Query the database's own metadata APIs. For Neo4j, use the built-in schema visualization procedure. For RDF, a SPARQL query surfaces all distinct predicate types.
``` # neo4j_adapter.py
def crawl_schema(driver):
  with driver.session() as session:
    return session.run(“CALL db.schema.visualization()”).data()

# rdf_adapter.py
SPARQL_PREDICATES = ”””
  SELECT DISTINCT ?p WHERE { ?s ?p ?o }
”””
```
2
The Semantic Translator
Convert the raw schema into a rich system prompt. The agent now has a cognitive map of the enterprise — relationships, entities, and traversal options — expressed in natural language.
``` def build_system_prompt(ontology: Ontology) -> str:
  lines = [“You are an agent with access to an Enterprise Graph.”]
  for rel in ontology.relationships:
    desc = nl_describe(rel) # “Navigate from X to Y via REL”
    lines.append(desc)
  return ”\n”.join(lines)
```
3
The Tool Factory
Wrap each relationship as a typed Python function and register it as an MCP tool. Queries are dynamically generated from the ontology — no hardcoded Cypher.
``` def traverse_relationship(
    start_node: str,
    relationship_type: str
) -> list:
  # Dynamically built from ontology — no hardcoding
  query = (
    f”MATCH (n {{name: ‘{start_node}’}})”
    f”-[:{relationship_type}]->(m) RETURN m”
  )
  return execute(query)

# Register as MCP tool endpoint
mcp_server.register_tool(traverse_relationship)
